# C12 — резолв без `go list` + фикс `$`-якоря: DONE

Дата: 2026-09-30. Smoke: **8/8 PASS**.

## Вопрос

Зачем ждать `go list` (100–327мс сабпроцесс) на каждом gd, если каталог
пакета выводится из файловой системы? Ответ: незачем в общих случаях.
Убрать совсем нельзя (версию модуля и replace без go не узнать всегда),
но сабпроцесс стал последним фолбэком вместо первого шага.

## Что сделано (`lua/keymap/pick.lua`, ~200 строк)

`resolve_import_dir(cwd, import_path)` — чистый резолв, только fs_stat/glob:
1. `go.work` выше → сразу nil (сложный граф — за `go list`).
2. `vendor/<import>` от корня модуля → готовый dir.
3. stdlib (первый сегмент без точки) → `$GOROOT/src/<import>`
   (`go env` один раз за сессию, кэш).
4. module cache: парс `go.mod` (require + replace, обе формы, кэш по mtime)
   → самый длинный префикс-модуль → `$GOMODCACHE/<esc>@<ver>[/rest]`
   (эскейп заглавных через `!`, локальные replace — от корня модуля).
   Версии нет в go.mod → glob `@*` + max версия.
5. Не вышло → nil → старый путь (`go list`, TTL-кэш).

Плюс по ходу найден и починен баг: якорь `$` в `cWORD`-матче ломал
qualified-ветку на `sql.DB)` / `TrimSpace(` — хвост после типа теперь
игнорируется (`cur_word == sym` по-прежнему отсекает ложное).

## Доказательства (спаны + PTY)

- stdlib `sql.DB`: `qual-resolve-pure` → прыжок в GOROOT, сабпроцесса нет;
  рядом в том же прогоне гонку выиграл LSP за 2.5мс (оба пути живы).
- vendor `widget.New`: pure-резолв 0.27мс → прыжок в `vendor/.../widget.go:7`.
