# ASCII-движение: анимации, которые несут информацию

> Статус: **фазы 1–2 реализованы (2026-10-13)**: пункты 1, 2, 3, 5, 6, 7, 8, 12; фаза 3 — дальше. Контракт фичи: меняешь поведение — сначала правь этот файл.

## Цель

Анимации в редакторе отвечают на вопрос разработчика — *что изменилось, где, идёт ли процесс,
чем кончилось* — и не отнимают ни фокус, ни CPU. Декоративных циклов нет.

## Правила

1. **Ноль работы в простое.** Таймер живёт только пока идёт эффект (`dev.fx.ticker`). В горячих
   автокомандах (CursorMoved, LspRequest, TermRequest) — сравнение чисел/строк, остальное лениво.
2. **Пороги.** Спиннер — только если операция дольше 150 мс (быстрое не мигает); вспышка-отклик
   ≤ 400 мс; значок-сообщение гаснет ≤ 1.5 с; итог фоновой операции висит до 60 с.
3. **Reduced motion.** `settings.ui_animations = false` (и headless): та же информация статично —
   глиф/цвет без таймеров, исчезает по одному отложенному `vim.defer_fn`.
4. **Не трогаем фокус, курсор, ввод.** Только extmarks, строка сверху (`_tabline`), статуслайн.
5. **Один язык.** Спиннер `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` (80 мс/кадр); рампа `@ # * + = - : .`; спарклайн
   `▁▂▃▅▇`; угасание — 3 ступени фона/цвета до нуля. Цвета палитры khold: красный — внимание/провал,
   teal — успех, кость `#eceee3` — текущее значение, серые `#888`/`#6b6b6b`/`#5a5a5a` — мета.
6. **`vim.b.large_file`, плавающие окна, `buftype ~= ""`** (кроме специально оговорённых) — без эффектов.
7. **Тестируемо.** Состояние и кадры — чистые функции модуля (`_frame(i)`, `_state(...)`), их
   проверяет regress-скрипт; приёмка — GIF через `tui-test record` + кадры-скриншоты.

## Фаза 1 — спецификация

### 2. `dev.lspwait` — спиннер медленного запроса
- `LspRequest` (одна автокоманда в `core/event.lua`): учитываются только методы, которые запускает
  пользователь: `textDocument/definition`, `references`, `hover`, `implementation`, `typeDefinition`,
  `rename`, `prepareRename`, `codeAction`, `signatureHelp`, `callHierarchy/*`, `workspace/symbol`.
  Фоновые (semanticTokens, inlayHint, documentHighlight, codeLens, diagnostic) — игнор.
- `pending` → через 150 мс, если запрос ещё висит и буфер запроса — текущий: virt_text в конце строки
  курсора `⠋ gopls` (имя клиента), серым; кадры каждые 80 мс. `complete`/`cancel` → снять.
  Несколько запросов — один спиннер на буфер. Без анимаций — статично `… gopls`.

### 3. Вспышка после `u` / `<C-r>`
- `u`/`<C-r>` (с count) → `normal! {count}u` → строки `'[`..`']` вспыхивают теми же ступенями, что
  след внешней правки (`fx.trail`), но короче (≤ 400 мс). Без анимаций — подсветка 400 мс, затем снять.
  Проверено: после undo/redo `'[`/`']` указывают на изменённый диапазон.

### 5. Значок завершения команды в терминале
- `dev.termmarks` на OSC 133;D: если ни одно окно не показывает этот терминал — запомнить
  `{buf, code, sec, cmd}` (cmd — текст строки приглашения после символа prompt, ≤ 24 символов).
  Строка сверху: `⌁ <cmd> ✓ 12.3s` (teal) или `✗ <code>` (красный), 60 с или до открытия терминала;
  клик (`%@…@`) — открыть терминал проекта. Медведь: `dev.bear.done("term", code == 0)`.

### 8. Значок позиции в quickfix
- `]q`/`[q`: после перехода — virt_text в конце строки `⟶ 3/17` (номер — кость, остальное серым),
  угасает за ~1 с тремя ступенями. Без анимаций — статично 1.5 с.

### 12. Реализации интерфейсов
- Интерфейс: `◆ 2 implementations · MemRepo, PgRepo` (≤ 3 имени, дальше `+N`), `◆ 1 implementation · X`,
  `◆ no implementations` (тусклее — мёртвый интерфейс). Структура: `◇ Reader, Stringer` — как было.
- Пока запрос в пути — `◆ ⠹` (спиннер), ответ «печатается» слева направо за ~150 мс.
- Группы `DevImpl` (глиф, `#5a5a5a`), `DevImplCount` (`#888888`), `DevImplName` (`#6b6b6b` italic) —
  в теме khold; модуль ставит их с `default = true` → `Comment` на случай отката темы.

## Фаза 2 — спецификация

### 1. Живые тесты
- `dev.test._execute` (mode test) стримит stdout `go test -json`; `testmarks._split` режет чанки на
  строки, `live_feed` → `_live_reduce` считает `done/total/fail` верхних `Test*` (подтесты — нет).
- Событие `run` — у `func TestX` в загруженных буферах спиннер `⠹ 1.2s` (после 150 мс), `pass/fail/skip`
  заменяет его обычным ✓/✗. Строка сверху: `go test ⠹ 12/40 · ✗2` (total = уже запущенные), после прогона —
  прежний итог `go test: …`. Один `fx.ticker(80)` на всё, пока идёт прогон; без анимаций — статичное `…`
  и перерисовка по событиям. qf, notify и диагностики конца прогона не менялись.

### 6. Конвейер `<leader>Ac`
- `dev.build.pipe` (шаги `pend|run|ok|fail`), сегмент `check [build ✓]━[vet ⠹]━[lint ·]`
  (`_pipe_text`): ✓ teal `StlMT`, ✗ `DiagnosticError`, `·` ожидание; висит 60 с после конца.
- Клик по шагу — `%N@v:lua._tl_check_click@` (N = индекс шага) → `pipe_open` → qf только с `[шаг]`-элементами.

### 7. Только новые ошибки
- `dev.newdiag` (автокоманды в `core/event.lua`): снимок ERROR-ключей (текст строки + сообщение) на
  `BufWritePre` (только `buftype == ""`, без `large_file`); `BufWritePost` взводит ожидание (5 с), первый
  `DiagnosticChanged` буфера сравнивает и один раз вспыхивает `fx.flash_rows` по новой ошибке.
  Shortcut: `flash_rows` держит одну вспышку на буфер — красится первая новая строка.
