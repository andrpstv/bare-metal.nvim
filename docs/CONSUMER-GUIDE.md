# Руководство потребителя

Этот документ — для человека, который поставил bare-metal.nvim и хочет им
пользоваться. Он не про архитектуру конфига: как устроен код, написано в
`docs/distro/`. Здесь только то, что нужно в обычный рабочий день.

Если вам нужно понять, что внутри, — вам не сюда.

---

## Первые пять минут

### 1. Поставить всё, что нужно

Одна команда, одно подтверждение:

```vim
:DistroSetup
```

Она покажет план — построчно, что именно скачает и откуда, — и спросит один раз.
Ничего не ставится молча. Ответ «No» означает, что не скачано ничего.

Что она умеет поставить: парсеры treesitter, языковые серверы и линтеры из
каталога дистрибутива. Чего не умеет: системные пакеты. `bash-language-server`
и `marksman` ставятся через npm/системный менеджер, об этом будет сказано в
плане отдельной строкой.

### 2. Проверить, что всё в порядке

```vim
:ConfigHealth
```

Проверяет бинарники, подключение LSP, тему и клавиши. Это первое, что стоит
сделать, если что-то ведёт себя не так.

### 3. Проверить подсветку синтаксиса

Откройте файл с расширением `.lua`, `.go` или `.sh` и посмотрите на цвета.
Если файл весь одного цвета — парсеры не собраны:

```vim
:DistroParsers --all
```

При первом запуске редактор сам напомнит об этом, если парсеров не хватает.

## Что умеет

**Языковой сервер.** Автодополнение, переход к определению, поиск ссылок,
переименование, диагностика. Работает для Go, Lua, Bash, JSON, HTML, C/C++,
Python, Dart — если установлен соответствующий сервер.

**Парсеры treesitter.** Подсветка, отступы, текстовые объекты. Собираются из
исходников только командой `:DistroParsers --all` (с подтверждением),
нужен C-компилятор. Сами при старте не ставятся — редактор только напомнит.

**Форматирование при сохранении.** Только через LSP (`textDocument/formatting`):
без сервера с форматтером — уведомление и пропуск, код не переформатируется.
Безопасная политика: `vendor/`, generated-файлы (`*.pb.go`, `*_generated.go`,
`*.gen.go`, файлы с маркером `Code generated … DO NOT EDIT`), module cache
и каталоги из `format_disabled_dirs` не трогаются (там чужой или
зафиксированный стиль) — один тихий хинт на буфер, принудительно — `:Format`.

**Линтинг.** `golangci-lint` запускается при сохранении Go-файла, по
BufWritePost. Нет бинарника — при загрузке придёт уведомление, линт молча
выключен.

**Git.** Хоткеи по изменённым hunks, стейджинг отдельным куском, blame,
diffview для сравнения веток и истории файла.

**Отладка Go.** DAP + delve: `<leader>db` — брейкпоинт, `<leader>dc` —
продолжить/старт, `<leader>dn`/`<leader>di`/`<leader>do` — шаги,
`<leader>dp` — пауза, `<leader>dt` — дебажить тест под курсором,
`<leader>dr` — REPL (фокус переходит в него сам), `<leader>de` — вычислить
под курсором, `<leader>dw`/`<leader>df` — переменные/стек,
`<leader>dx` — стоп. `<leader>du` — единый инспектор (фреймы, scopes,
watches) в правом сплите: `<CR>` — перейти к фрейму/раскрыть значение,
`d` — убрать watch, `r` — обновить, `q` — закрыть; `<leader>dW` —
добавить watch. Нужен `dlv` (`:DistroBinaries`). Окна REPL/виджетов
закрываются по `q`; виджеты (scopes/frames/hover) при завершении сессии
закрываются сами, REPL остаётся для просмотра вывода.
Нюанс delve: условие на строке `if x := ...` не видит `x` (переменная
ещё не создана) — ставьте условный брейкпоинт строкой ниже.
Windows: отдельное консольное окно не всплывает; если старт висит дольше
20с — проверьте, что `dlv` в PATH, файрвол/антивирус не режут localhost
и `dlv dap` запускается вручную (текст ошибки delve показывается прямо
в уведомлении).
Платформы: отладка через delve проверена на macOS; на Windows требуется
AMD64-сборка delve (на ARM64 delve официально не собирается — там `dt`
честно сообщает об отсутствии бинарника).

**Терминал.** Встроенный, project-local, переживает toggle: `<leader>tt`
показать/спрятать (float), `<leader>ts`/`<leader>tv` — split/vsplit,
`<leader>te` — выполнить команду в терминале проекта.

**Тесты.** `go test -json` с разбором: падения — в quickfix, итог — нотифаем.
`<leader>ta` (алиас `<leader>at`) — все тесты, `<leader>gt` — тест под
курсором,
`<leader>tr` — перезапустить упавшее (читает итог ta/gt),
`<leader>tc` — покрытие (знаки + процент), `<leader>tC` — убрать знаки,
`<leader>tb` — benchmark под курсором (иначе весь пакет; итог с ns/op),
`:TestOutput` — сырой вывод последнего прогона, `:TestBench` — то же,
что `<leader>tb`.
Codelens «run test» / «run benchmark» (`<leader>cl` на линзе) идёт через
тот же движок — с выводом, quickfix и rerun, а не вслепую.

**Переименование (`<leader>rn`).** Cross-file правки сразу пишутся на диск
(только затронутые файлы); итог — нотифаем с числом файлов.

**Замена по проекту.** `<leader>sr`: паттерн → поиск через rg → preview
в quickfix → подтверждение (всё / этот файл / отмена) → применение.

**Git UI.** `<leader>G` — Neogit (status/commit/push/pull/log) поверх
gitsigns+hunks. **Проекты.** `<leader>wp` — переключение (реестр + сессии),
`<leader>ws` — сохранить сессию корня; автсейв на выходе включён
(`project_autosave`), восстанавливается только по запросу.

**Пакетный менеджер.** `:Distro` — установка и обновление плагинов из
каталога, всё с подтверждением.

## Что доустановить руками

Редактор запустится и без этого. Без этого он просто не сможет делать часть
вещей. Go — основной поддерживаемый язык; Bash и Lua — опциональны:
отсутствующий опциональный сервер при старте помечается как optional
с подсказкой, откуда его взять (`:DistroBinaries` — только с вашего
подтверждения, сам ничего не ставит).

| Что | Зачем | Установка |
| --- | --- | --- |
| `gopls` | всё для Go | `go install golang.org/x/tools/gopls@latest` |
| `lua-language-server` | всё для Lua | инструкция на github.com/LuaLS/lua-language-server |
| `bash-language-server` | всё для Bash | `npm i -g bash-language-server` |
| `vscode-json-language-server` | JSON | `npm i -g vscode-langservers-extracted` |
| `vscode-html-language-server` | HTML | `npm i -g vscode-langservers-extracted` |
| `clangd` | C и C++ | `brew install llvm` / `apt install clangd` |
| `python-lsp-server` | Python | `pip install python-lsp-server` |
| `golangci-lint` | линтер для Go | `go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest` |
| `gofumpt` / `stylua` / `shfmt` | форматтеры | `go install mvdan.cc/gofumpt@latest` и т.д. |
| `ripgrep` | ускоряет поиск | `brew install ripgrep` / `apt install ripgrep` |
| C-компилятор | нужен для парсеров | `xcode-select --install` / `apt install build-essential` |

Большинство из этого ставится через `:DistroSetup`. Ручная установка нужна там,
где бинарник должен оказаться в системном `PATH` (npm-пакеты, часть
форматтеров).

Замечание про `tar`/`unzip`/`cl`: `:DistroTools` проверяет `tar` (нужен для распаковки `.tar.gz` архивов), а `unzip` проверяется только в `:ConfigHealth` как fallback для `.zip` на Linux (на macOS/Windows распаковка zip обычно уже есть в системе); `cl` (MSVC) тоже упоминается только в health как один из допустимых C-компиляторов для сборки парсеров, в `manifest.tools` его нет — рассинхрон осознанный, код не менялся.

## Если тормозит

Идите по порядку, начиная с замера.

**1. Измерьте, а не гадайте.**

```vim
:DistroBench
```

Покажет время открытия файла и сравнит с чистым Neovim. Если разницы нет —
тормозит не запуск, а что-то внутри сессии.

**2. Отложите тяжёлое.**

```vim
:PerfDeferOn
```

Автодополнение и часть фоновых задач переносятся с первого `:edit` на первый
`InsertEnter`. Первый кадр становится дешёвым; работа не отменяется, она
переносится. Постоянно включить — переменная окружения `NVIM_PERF_DEFER=1`
(старые `NVIM_TURBO` / `NVIM_TURBO_MODE` тоже читаются).

**3. Облегчённый режим.**

```vim
:PerfLeanOn
```

Один переключатель вместо пяти: выключает самые дорогие фоновые анализы gopls
(fieldalignment, восемь codelens) и прочее. Постоянно — `NVIM_PERF_LEAN=1`
(старый `NVIM_WEAK_HW=1` тоже читается).

**4. Посмотрите, где именно.**

```vim
:DistroTrace
```

Дерево операций с таймингами: показывает, что занимает время — загрузка модуля,
ответ сервера, пикер. Элементы можно раскрыть и увидеть, где именно вложились
миллисекунды.

**5. Проверьте, не дублируется ли работа.**

`:DistroDiag` показывает, подключился ли LSP к текущему буферу, какие
capability ушли серверу и куда. Частая находка — сервер подключился, но запросы
идут в буфер, для которого он не подходит.

## Если что-то не работает

**Нет подсветки синтаксиса.** Нет парсеров. `:DistroParsers --all`. Нужен
C-компилятор — проверьте `cc --version` или `gcc --version`.

**Нет автодополнения.** Нет языкового сервера. `<leader>li` покажет, есть ли
клиент (без сервера маппинга вообще нет — поставьте сервер из таблицы выше).
Если клиент есть, а подсказок нет — проверьте `perf_defer` (дефолт `true`:
тяжёлое едет после первого кадра) и наличие `cmp` в `:Distro`.

**`.editorconfig` / линтер не срабатывает.** Проверьте, что бинарник в `PATH`:
`vim.fn.executable("golangci-lint")` должно вернуть `1`.

**Формат при сохранении не работает.** Нужен форматтер. Он ищется автоматически;
при старте приходит уведомление, если не найден. Временно отключить —
`<leader>ft`.

**Компания за прокси, ничего не качается.** Настройте зеркало: `:DistroMirror`.
Смотрите `docs/distro/06-corporate-mirror.md`.

**Проверить, что конфиг вообще загрузился.**

```sh
nvim --headless -c 'qa!' && echo OK
nvim --headless -c 'checkhealth core' -c 'qa!' # именно с qa!, иначе вис
./scripts/smoke-test.sh
```

## Про настройки

Всё переопределяется в `lua/user/settings.lua` — этот файл накладывается
поверх `lua/core/settings.lua` и имеет приоритет. Он создаётся установщиком
из `lua/user_template/settings.lua` в момент установки; при ручном клоне
скопируйте сами (`cp -r lua/user_template lua/user`) — автобутстрапа нет.
Если файла нет, пользовательских настроек просто нет (конфиг работает
на дефолтах).

```lua
-- lua/user/settings.lua (целиком: нужны local и return)
local settings = {}

settings["colorscheme"] = "khold"
settings["format_on_save"] = false

return settings
```

Что стоит знать о конкретных настройках:

- `treesitter_deps` — список языков, для которых собираются парсеры. Сузьте
  его, если вам не нужен весь набор: сборка идёт локально и занимает время.
- `parser_bootstrap` — проверка парсеров при старте. Поставьте `false`, если
  парсеры ставит внешний процесс (образ, DevContainer).
- `leader_help` — всплывающая подсказка по `<leader>`. `:LeaderHelp` работает
  в любом случае.
- `leader_help_delay_ms` — пауза после `<leader>` до всплытия подсказки
  (по умолч. 3000мс, аналог which-key `delay`, от `timeoutlen` не зависит).
  Быстро допечатали — ничего не мигает; `false` у `leader_help` гасит всё.
- `perf_defer` — откладывать тяжёлое до первого кадра/`InsertEnter`.
  Экономии суммарного времени это не даёт: работа переносится, а не отменяется.
  Оставьте как есть.
- `perf_lean_axes` — оси облегчённого режима (`:PerfLeanOn` включает пресет,
  сам lean по умолчанию выключен — нужен `NVIM_PERF_LEAN=1` или команда).
- `disabled_plugins` — kill-switch плагинов без форка: имена из
  `lua/distro/manifest.lua` (поле `name`, например `"trouble.nvim"`).
  Лоадер скипает их везде. Точечно — `lua/user/configs/<имя>.lua`,
  вернуть `false`: скипает только setup, плагин остаётся загруженным.

Полный список с комментариями — в начале `lua/core/settings.lua`.

### Свои кеймапы

Перебиндить клавиши без форка: `lua/user/keymap/*.lua` (шаблоны лежат в
`lua/user_template/keymap/`, все подмодули уже на месте: `core`, `completion`,
`editor`, `lang`, `tool`, `ui`). Формат записи:
`{ ["n|<leader>x"] = { rhs = "<Cmd>...<CR>" | function | false, opts = {...} } }`,
`false` целиком вместо таблицы — удалить маппинг, `opts.buffer = buf` —
локально буферу, `"nv|ga"` — сразу два мода. Глобальные собираются в
`user.keymap.init`, LSP-маппинги буфера — `user.keymap.completion.lsp(buf)`
(пример внутри шаблона). Контракт — `lua/modules/utils/keymap.lua`.

## Сессии

Сессия сохраняется по рабочему каталогу: `<leader>ss` — сохранить,
`<leader>sl` — загрузить. Файл кладётся в data-каталог, не в репозиторий, и у
каждого проекта свой. Если сессии для текущей папки нет, вы получите понятное
сообщение, а не ошибку.
